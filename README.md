
# Concrete Compressive Strength Prediction using Machine Learning

**Assignment:** Comparative Performance Analysis of Machine Learning Models with EDA and Model Deployment  
**Problem type:** Supervised regression  
**Dataset:** UCI Concrete Compressive Strength (Yeh, 1998)

## Project contents
- `src/data_utils.py` — obtains and validates the dataset.
- `src/build_report.py` — builds a results-filled DOCX report with generated tables and figures after training.
- `src/train.py` — EDA figures, data audit, three baseline models, holdout evaluation, RandomizedSearchCV tuning, permutation importance, model saving, and report-ready results.
- `app.py` — Streamlit prediction app using the trained model.
- `notebooks/Concrete_Compressive_Strength_Project.ipynb` — notebook launcher for the full reproducible pipeline.
- `report/Project_Report.docx` — academic report structure and methodology.
- `requirements.txt` — Python dependencies.
- `data/README.md` — dataset source and details.
- `outputs/` — generated tables, charts, and results after running training.
- `models/` — generated trained model and metadata after running training.

## Dataset
Official source: https://archive.ics.uci.edu/dataset/165/concrete+compressive+strength  
DOI: https://doi.org/10.24432/C5PK67  
Citation: Yeh, I.-C. (1998). *Concrete Compressive Strength*. UCI Machine Learning Repository.  
The dataset has 1,030 observations, 8 numerical predictors, and 1 numerical target (MPa). It is licensed CC BY 4.0; cite the source and follow its license terms.

## Run locally
Python 3.10+ recommended.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
python src/train.py
python src/build_report.py
streamlit run app.py
```

The first run fetches the dataset using `ucimlrepo` and caches it in `data/`. An internet connection is required for the initial fetch. If running on Colab, upload the project folder or clone your GitHub repository, install requirements, then run the training command.

## Reproducibility and leakage prevention
- Fixed random holdout split: 80% training, 20% testing, random state 42.
- All learned imputation/scaling steps are inside scikit-learn Pipelines.
- Scaling is applied to Linear Regression pipeline; tree models do not require scaling.
- Hyperparameter search uses only the training set and 5-fold cross-validation. The held-out test set is not used to select parameters.
- The same holdout split is used to compare baseline models and the tuned model.
- Exact duplicate rows and outliers are reported for investigation rather than automatically removed; repeated measurements can be legitimate. The dataset has no missing values according to UCI, but the code checks it again.

## Models
1. Linear Regression
2. Random Forest Regressor
3. Gradient Boosting Regressor
4. Random Forest after RandomizedSearchCV (improvement experiment)

## Evaluation
Regression metrics: MAE, MSE, RMSE and R². The project also creates actual-vs-predicted and residual plots, a permutation importance chart, and model comparison charts. Accuracy, precision, recall, F1, confusion matrix and ROC-AUC are classification metrics and are not appropriate for the continuous MPa target unless the problem is explicitly reformulated as classification (not done here).

## Limitations
The model is an educational estimator trained on a limited public dataset. A random row split may place observations from similar mixtures in both train and test sets. Scores do not establish safety, code compliance, or generalisation to new cement sources, aggregates, admixtures, climates, or production plants. Before real engineering use, validate with independent project-specific laboratory data and an appropriate validation design. Never use predictions as a substitute for required material testing.
